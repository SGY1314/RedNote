# RedNote 笔记助手

面向本地生活探店场景的小红书原生小程序。商家提供参考素材，用户扫码查看、根据真实体验编辑文案，再主动打开小红书编辑器。

## 当前流程

商家通过后台准备文案与素材并生成二维码。手机用小红书扫一扫扫描二维码，自动进入“笔记创作”页，完成载入、接收授权校验及原生组件参数准备。稿件载入后自动把标题、正文和话题完整复制到剪贴板；用户修改文案后停顿 400ms 更新复制内容，轮询不会反复复制。用户可以修改标题、正文，点击“编辑”调整话题，点击缩略图查看全部图片。底部“发小红书”就是官方原生组件，点击直接打开官方发布页，小程序内没有再次确认。是否发布由用户在官方页面确认，返回小程序不会被记为发布成功。

首页展示品牌介绍、三步探店创作流程、参考笔记和使用说明。首次打开即有咖啡、家常菜、烘焙三组内置参考笔记，点击卡片进入同一个“笔记创作”页，可查看预备图片、修改标题正文和话题、主动复制文案。卡片标明“示例”，创作页标明“原创 AI 配图”，不虚构实际店铺、到店体验或互动数据。已经扫码取得授权的稿件也显示在首页；这些最近稿件和手机修改仅存于内存，最多四份，不能超过原有交接有效期；退出小程序后不保留。手机修改不回写工作台数据库，重复校验同一份稿件时保留修改，换稿或过期后清除。

商家后台继续复用现有网站数据与 HTTPS 接口，原有扫码参数、短期授权和媒体地址格式保持兼容。客户界面不展示工作台地址、票据输入、导入说明、开发环境报告等实现细节；加载和发布错误用可操作的客户提示表达。

仍向官方组件传递标题、正文和话题；用户已在真机观察到只带图片的情况，暂不能确定在哪一侧丢失。进入页面后自动复制完整文案，也可手动点击“一键复制文案”；若发布页文字为空，可长按粘贴后整理标题与正文。只有复制回调成功才显示“文案已复制”；失败或超时提示重试，不阻止已就绪的官方发布入口。页面隐藏时暂停复制并忽略迟到回调，过期稿件不复制。不读取剪贴板，也不在后台复制。详见[手机发布接入说明](../../docs/MOBILE_PUBLISH.md)。

应用只保留首页和笔记创作页，不提供手动输入或复制取件码入口。JSON 导入、状态演练和独立环境检查页已移除。发布按钮在接收状态有效、全部图片加载成功、运行环境支持并重新确认授权后才可用；文字修改经过短暂合并后重新准备参数。后台准备不会自动打开发布器，不读取剪贴板，也不登录账号或提交笔记。视频可预览，当前编辑器导入仅支持图片稿件。

内置参考图片随小程序打包，本地即可预览、编辑和复制。官方发布组件使用同一图片的 HTTPS 地址，准备按钮时检查图片响应；没有配置 HTTPS 服务时仅允许本地浏览与复制。公开示例使用固定白名单 `referenceId`，不领取、读取或保存私有稿件凭证；带扫码参数的入口仍优先走原有授权流程，不回退到示例。配图及其SHA-256清单位于 `assets/reference`，网页公开副本位于 `web/public/reference-notes`。

## 连接与预览

维护源码位于本目录；开发者工具副本为 `C:\Users\asus\Desktop\RedNoteapp\RedNote`。在仓库根目录执行：

```powershell
.\scripts\sync-miniapp.ps1 -Destination 'C:\Users\asus\Desktop\RedNoteapp\RedNote'
.\scripts\connect-miniapp-cloud.ps1 -ApiBaseUrl 'https://8.138.93.241.sslip.io' -EditorCheck
```

同步保留开发副本的 AppID 和本地连接配置。随后在小红书开发者工具重新编译、生成预览码，用有开发权限的账号在手机打开。工作台生成业务二维码后，用小红书扫一扫直接打开稿件；凭证随二维码参数传入，不需要输入。

仓库默认未配置服务，内置参考笔记仍可本地查看；真实扫码稿件和官方编辑器导入需要手机可访问的 HTTPS 服务，连接细节见 [CLOUD_DEVELOPMENT.md](CLOUD_DEVELOPMENT.md)。

用户已实测开发者账号可扫描工作台二维码进入小程序。普通账号的可用范围仍取决于平台版本和权限；这次界面更新不改变版本或成员权限。

## 模块与验证

- `pages/index`、`pages/publish`：接收与预览页面。
- `features/publish`：状态、媒体检查和原生编辑器生命周期。
- `features/publish/draft-editor.js`：手机端文案编辑、计数、话题解析和复制文本。
- `features/publish/recent-drafts.js`：本次使用中的稿件卡片与修改缓存，不使用持久化存储。
- `features/publish/publish-entry.js`：接收与按钮准备的调度、编辑合并、隐藏和卸载取消。
- `features/publish/text-handoff.js`：整份文案自动及手动复制、编辑合并、迟到回调与超时处理；不负责发布操作。
- `features/publish/customer-messages.js`：面向探店用户的状态和错误文案。
- `features/references`：公开参考笔记目录与入口白名单。
- `assets/reference`：三张原创示例图片与尺寸、大小、SHA-256 清单。
- `features/device-check/policy.js`：运行环境和编辑器参数规则。
- `services`：真实交接请求、短期接收凭证和媒体参数。
- `services/reference-gateway.js`：公开示例的本地预览与 HTTPS 图片检查，与私有接收授权隔离。
- `utils/contract.js`：快照、长度、URL、到期和扫码参数校验。
- `tests/fixtures`：仅供自动测试的示例与模拟网关。

在仓库根目录运行：

```powershell
node --test miniapp/RedNote/tests/*.test.js
npm.cmd --prefix web run test:mobile
```

小程序有93项规则和页面绑定测试；新增网页手机发布测试检查二维码创建、重复点击、撤销、状态恢复及1720/823/547/390像素布局，截图在 `web/test-results/mobile-publish/`。桌面检查不模拟官方原生发布能力。

测试不使用真实账号发布；开发者工具编译和手机组件表现仍需预览验证。完整操作见[手机发布说明](../../docs/MOBILE_PUBLISH.md)。

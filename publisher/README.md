# 扫码发布组件

工作台使用本机浏览器操作小红书网页，支持扫码登录、图文和单视频预发布（自动上传填写、本人手动发布）。这不是小红书官方开放接口；网页结构、登录验证和内容限制变化时可能需要更新适配。

## 本地修改

1. 强制监听 `127.0.0.1:18060`，要求内部服务令牌，拒绝浏览器 Origin。仅开放登录状态、二维码、断开账号、图文／视频发布及本人帖子数据读取；不开放 MCP、搜索、评论等接口。
2. 使用 go-rod 直接启动电脑已安装的 Chrome 或 Edge，保持浏览器沙盒；不运行 `leakless.exe`，不自动下载上游浏览器，不启用上游指纹和隐身脚本。每次操作使用独立的临时浏览器配置，不读取日常浏览器的用户配置。
3. Windows DPAPI 加密保存登录会话。正常退出清理临时浏览器目录；强制中断可能遗留临时浏览器文件，勿分享数据或临时目录。
4. 发布请求必须包含预期账号 ID。上传前在同一浏览器再次读取实际账号并匹配；断开账号会取消未结束的扫码会话。
5. 图文与视频请求只执行上传和填写，保留可见的专用官方窗口。返回 `prepared: true, verified: false`，主程序仅记为 `manual_ready`，不会自动点击发布或填写发布时间。准备异常也保留窗口供本人检查和补填。
6. 修复二维码提取异常时的浏览器清理，补充接口隔离及 DPAPI 加密测试。

## 构建和运行

Windows 下由 `scripts/setup.ps1` 构建，`scripts/start.ps1` 启动，`scripts/stop.ps1` 核对进程身份后停止组件及其浏览器子进程。

内部配置：`AUTH_TOKEN` 取自主程序数据目录 `publisher.token`；`COOKIES_PATH` 指向 `data/publisher/session.dpapi`；`WORKBENCH_BROWSER` 指向已安装的 Chrome／Edge。令牌不通过命令行参数传递。

```powershell
# 在项目根目录执行
. ./scripts/environment.ps1
Push-Location publisher/upstream
go test . ./cookies -run TestWorkbench -count=1
go build -trimpath -o ../../bin/publisher.exe .
Pop-Location
```

## 用户流程和当前边界

发布管理 → 扫码连接 → 手机确认登录 → 查看账号 → 选择发布稿 → 准备上传 → 打开预发布窗口 → 核对文案、媒体顺序、封面和可见范围 → 本人在官方页面点击发布 → 回工作台记录已发布。

- 图文的选定封面作为第一张上传图片；独立封面也包含在确认预览中。
- 单视频暂使用平台默认封面。选择自定义视频封面时会阻止在线提交，可移除封面重新建立快照，或下载单个素材后自行发布。
- 本地发布校验标题 1–20 字、正文与话题不超过 1000 字、最多 10 个话题；平台仍可能实施其他限制。平台报错不伪装成成功。
- 运行中的任务在重启后转为待核实。请先到创作平台确认结果，再记录已发布，或明确核实未发布后重新提交。
- 使用用户自己的账号。验证码或平台限制需要用户自行处理，不提供验证码绕过。
- 上传准备成功不代表已发布。本人确认官方发布成功后，通过“记录已发布”确认发布时间（无需填写作品链接）。

自动化测试只使用模拟接口或本地临时数据；真实账号扫码与实际发稿应小规模人工验收。

## 本人帖子数据适配

`POST /api/v1/monitor/own-notes` 必须传入 `account_id`。在同一浏览器检查真实登录账号，再从本人主页读取最多 20 个已加载的作品；逐条检查作者 ID，详情读取限制 10 秒，总操作限制 5 分钟。不滚动抓取全量历史，不读取收藏、点赞列表或评论正文。

返回限定字段：账号、作品 ID、标题、类型、发布时间及互动计数字符串。详情失败保留主页卡片字段；空字段表示未知。当前来源未提供阅读量，保持空值。网页原始状态、会话数据、访问令牌及评论不返回主工作台。网页适配仍依赖正常扫码登录以及平台当前页面结构，模拟接口通过不代表真实账号联调通过。


## 2026-10-16 小红书扫码登录识别修复

- 不再以单一 `.main-container .user .link-wrapper .channel` CSS 元素判断扫码成功；识别页面当前用户状态（含 Vue value 包装）或官方侧栏「我/个人主页」链接，校验账号 ID、游客状态及可见登录弹窗。不读取笔记作者作为当前账号，不凭 Cookie 存在认定登录。
- 扫码使用可见的专用浏览器，用户可在同一会话完成官方验证。后台读取已有页面，不反复导航，也不因查状态另开浏览器。
- 等待扫码、验证中、需要官方验证、过期、失败和已登录分别回传。每次观察有 3 秒上限，整体扫码等待 4 分钟；不再让等待元素的无限重试遮蔽状态。
- 连续两次核实同一账号后，在当前二维码序号保护下保存加密会话，只有保存成功才返回登录成功。新二维码、退出与旧回调隔离；保存失败显示固定错误，不回传凭据。
- 登录完成状态短暂缓存 30 秒，后续状态查询重新验证已保存会话。前端每 2 秒查看进度，过期或失败停止轮询并清除二维码。
- 验证：登录会话、加密凭据和状态转发 Go 定向回归通过；网页识别 JS 模拟用例、前端逻辑和布局回归通过。未代用户扫码，真实官方页面登录仍需本人重启后验收。

## 小红书预发布与手动提交

- 新增内部 `/prepare`、`/prepare_video`；旧 `/publish` 路由也只准备，不提交。新版工作台不会在新接口缺失时回退旧自动发布接口，因此更新时需一起重启主程序与发布组件。
- 每份稿件保留独立的可见官方窗口，`POST /prepare/editor` 只激活原窗口，不重新上传。`DELETE /prepare/editor` 在用户核实未发布后关闭旧窗口；退出账号或正常停止组件关闭保留的窗口。
- 刷新工作台不会销毁预发布窗口。重启软件或手动关闭官方窗口后，先核实是否已发布；未发布可点击“核实未发布，重新准备”。窗口内容不会作为可恢复官方草稿自动保存。
- 任务完成仅代表自动填写流程完成，仍需本人预览官方页面的素材、文案、封面和可见性，最后点击官方发布按钮。
- 回归包含准备成功不写发布时间、重复准备拦截、旧服务不回退自动提交、窗口复用与关闭、手动登记结果，以及图文/视频填充调用链不能进入最终发布函数。模拟测试不代表实际平台上传已验收。

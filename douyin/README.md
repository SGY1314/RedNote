# 抖音适配器

Node.js 22+、Playwright **1.56.1**（package-lock.json 固定）、本机 Microsoft Edge。Gin 按需启动 worker.mjs，以私有标准输入输出通信，不额外监听端口。安装：在此目录运行 `npm ci --ignore-scripts`，或执行项目 setup.cmd。

使用独立临时浏览器上下文。登录会话由 Gin 使用 Windows DPAPI 保存到数据目录的 douyin.session.dpapi。采集使用新的独立上下文；不读取个人 Edge 配置目录。登录和发布的原始响应、Cookie、storageState 不写日志，不进入数据库快照或前端。Node 协议仅返回经过白名单映射的错误码。

二维码取自官方 `creator.douyin.com` 页面；读取创作者中心已认证的 user info UID 和昵称后，即可连接并准备上传，不再要求另外登录抖音主站。不能单凭 Cookie 判定登录；上传准备、提交前与结果查询仍核实创作者中心账号，禁止换账号后沿用旧稿件预览。协议、验证码与实名认证由用户在“打开专用官方浏览器”中处理。此入口切换浏览器时会使旧预览失效。

扫码状态包括“待扫码”“已扫码，待手机确认”和“创作者中心已连接，可准备上传”。每次状态查询都会把当前浏览器 storageState 交给 Gin，并由 Windows DPAPI 加密保存，因此有效会话可在适配器重启后恢复。账号检查只访问创作者中心，不受主站登录或主站网络失败影响。主站登录不能代替创作者中心登录，main_verified 仅保留为兼容信息，不作为发布前提。会话失效或平台要求重新验证时仍需本人处理；未通过真实账号上传联调，不宣称所有官方页面布局都已兼容。

准备与提交分开。准备上传文件、填写正文、设置可见性与选定封面，回读编辑器并保留其内容摘要和官方截图。用户必须核对截图中的素材顺序与封面。最终提交重新比较文件哈希、账号与编辑器摘要，只点击一次发布。只有可靠的提交响应作品 ID 才能进入“已提交／审核中”；需要作品管理页证明才能记为已发布。结果不明禁止自动重试。

### 2026-10-15：上传可见范围兼容

可见范围优先限定在「谁可以看」一行，支持自定义单选的 checked/selected 状态、原生 radio 和 ARIA radio；没有该行的旧页面保留带说明文字的 radio 标签匹配。已选正确范围时不再点击，修改后、预览时和提交前均读取实际状态。无法识别或多个选项同时选中时停止，不假设公开，不读取相邻「同时发布／保存权限／发布时间」的选择。

后续兼容：好友可见不是必需项，允许选项说明、标签空格和十层包装；检查同源官方 iframe 内的设置，多个匹配仍拒绝。准备时滚动到可见范围/发布设置，并等待至多约三十秒的控件轮询（不含滚动和浏览器调用耗时），处理延迟加载。仍需真实官网验收，不以模拟测试通过代表上传成功。

选中状态使用同一选项内的一致性检查，兼容原生、ARIA、data 属性和显式 checked/selected 样式标记；多个标记一致可接受，冲突则停止。初始未知时选择目标一次再回读，无法确认不继续提交。失败后自动保存 `logs/douyin-visibility.json`，只含有限结构与状态枚举，不含文案、账户、Cookie、URL、原始类名或页面源码；供后续检查真实失败控件使用。每次可见范围失败覆盖上次诊断，检查 time 字段避免混淆旧记录。

编辑器核对现在分字段报告错误。标题/正文的换行编码和 NBSP 会在两端统一，但不删除内部空格、段落或话题；填入后失焦并等待回读稳定。视频可读取 source 子元素地址，封面图片不视为上传的视频。核对失败保存 `logs/douyin-editor.json` 的匹配布尔值、字数和媒体数量，不记录文案或媒体地址。正式提交前仍检查本地文件摘要、账号、文案、可见范围和预览签名。

正文以段落 DOM 序列化，显示用 innerText 仅作差异诊断，避免 CSS 造成额外换行；不通过删除全部空白来放宽校验。隐藏视频仅在加载了视频尺寸/元数据并属于可见预览容器时可核实。schema 2 诊断补充空白/占位字符计数、差异位置和媒体源/加载状态布尔值，不含具体文字或 URL。

schema 3 增加 ignoredAddedZWSP：原稿没有 U+200B，且回读仅删除该字符即可与原稿逐字一致时，将其作为编辑器新增占位字符接受；不删除原稿自带的 U+200B，也不忽略任何其他内容差异。确认快照使用原稿规范化正文，视频素材缺失仍单独阻止准备。

### 上传到官方编辑页与人工继续

准备上传从一开始使用可见的专用 Edge，会话从既有上下文或加密存储恢复。执行文件选择、填写文案及官方上传等待后，如果最终编辑器核对返回明确的标题/正文/可见范围差异或媒体未识别，则返回 `manual_review` 交接结果，并保留浏览器。该结果没有 prepared_id、确认令牌或 verified=true，不声称上传完成，也不会触发正式提交。账号、文件、上传控件和网络等其他失败仍报错。

发布管理显示“待官网核对”和“继续官方编辑”。继续操作只将对应稿件的编辑页带到前台，不导航首页、不重复上传；稿件 ID 不符、页面关闭、离开编辑器或重启后返回明确失效提示。服务器重启将交接状态失效。正式发布状态仍需可靠平台回执或本人记录，不会因为交接成功而标记已发布。

`npm test` 包含控件模拟测试。另有仅访问本地 HTML 的 Edge DOM 测试；在能启动 Edge 的普通 PowerShell 中设置 `$env:WORKBENCH_BROWSER_TESTS='1'` 后执行 `node --test visibility-dom.test.mjs`（当前目录为 douyin）。默认跳过此浏览器测试。本轮受限环境启动 Edge 失败，未完成实际官网上传验证。

### 视频上传接口网络修复（2026-10-15）

官网公开上传脚本使用 vod.bytedanceapi.com、imagex.bytedanceapi.com 及 open.bytedanceapi.com，适配器现允许这些精确 HTTPS 子资源主机，保留地址校验及其他网络限制。官方编辑页出现“上传失败”时直接返回 upload_failed，不以文案填入、发布按钮可用或人工交接表示上传成功。每次准备上传后可查 logs/douyin-upload.json 的时间、阶段、域名级失败计数；不含完整请求地址或凭据。修改后重启工作台，再重新上传；已有失败浏览器需重新建立上传流程。

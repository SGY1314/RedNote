# OCR 返回“请提供图片”

## 手动选择图片（2026-10-11）

采集或重新采集只下载图片，不自动发起图片 OCR。打开笔记详情 → 原文与媒体，勾选需要识别的图片，再点击“提取所选图片文字”（每次最多 50 张）；也可逐张点击“提取文字”。未勾选图片不会创建 OCR 任务。重复提交正在排队或运行的图片复用原任务。

新版启动时取消旧版未标记为手动提交、处于排队／待配置／失败状态的 OCR 任务，防止补齐密钥后批量自动运行；旧版运行中断任务仍保留待核实状态。新手动任务在重启后保留，重试也标记为手动操作。已有文字结果保留。视频转写行为不在此次调整范围。

模拟回归覆盖完整图片下载后不创建 OCR、仅为勾选图片创建任务、无效批次不部分提交、重复任务去重、单图按钮、手动重试和旧任务启动恢复。

## 图片模型配置排查

2026-10-11 排查发现：OCR 设置选用了 `qwen-plus`，本地图片已作为 Base64 的 `image_url` 传入，但服务返回“请提供图片，我才能提取其中的文字内容。”，旧实现把这个回复保存成了成功结果。

本机 OCR 模型已更正为 `qwen3.5-ocr`，原有接口地址及加密密钥保持不变。模型与调用方式参见[百炼文字提取文档](https://help.aliyun.com/zh/model-studio/qwen-vl-ocr)。实际调用仍需要该模型的权限和额度；本次未执行付费请求。

代码改动：从本地图片内容检测 MIME，限制实际读入大小，检查图片状态；对明确索要图片的已知回复和输入不可读标记报错，不创建提取结果。设置页说明需要视觉/OCR 模型。

模拟测试核对实际图片字节、Base64、MIME、模型、接口和鉴权，覆盖错误回复不入库、有效结果保存和视频不得作为 OCR 图片提交。

使用：重启工作台并刷新页面，在笔记详情的图片下方重新点击“提取文字”，随后查看“OCR / 转写”。历史错误回复仍保留，不会因修改配置自动变成新结果；已建立的仿写来源快照也不自动改动。
